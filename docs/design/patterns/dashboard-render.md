# Dashboard: design tokens and code rendering

The palette and type scale, the Timeline event taxonomy, and the shared syntax-highlighting / word-level diff renderer.

Detail for patterns indexed in `CLAUDE.md`. Each entry states the rule and the failure it prevents — the history is the point, so it is kept verbatim rather than summarized.

- **Centralized design tokens (calm, semantic palette + type/spacing scales)**: `css/reset.py` is the single source of truth for the dashboard's look. Color is a small semantic set — one primary `--accent` (+`--accent-soft`), three status colors `--status-success`/`-danger`/`-warning` (each with a `*-soft` tint), the `--diff-*` family, one distinct `--compare-accent` (the only purple, so a compare-pick never reads as the blue selection), and a de-saturated Python-syntax `--tok-*` ramp. Three genuinely distinct neutral surfaces (`--bg`/`--surface`/`--surface-2`), three text levels (`--text-1/2/3`, secondary darkened to `#5a5a5a` for contrast), a type scale (`--text-xs`=11px floor … `--text-lg`, plus `--font-ui` sans for prose/UI and `--font-mono` for code/values), a 4px spacing scale (`--space-1..6`), and `--radius`/`--radius-sm`. Legacy names (`--fg`, `--muted`, `--card-bg`, `--code-bg`, `--green`, `--red`, `--yellow`, `--blue`, `--purple`, `--y`) are kept as thin aliases so older modules render unchanged; new/edited rules should reference the semantic tokens, not raw hex/rgba. **Critical dark-mode rule**: any alias whose value is `var(--primitive)` must be redeclared in **both** `:root` *and* `body.dark`. A custom property that aliases another resolves at the scope where it's declared and inherits that frozen value — so an alias defined only in `:root` keeps its *light* value in dark mode even when the primitive it points at (`--surface`, `--text-1`, …) is overridden under `body.dark`. (This regressed once: the legacy aliases were left out of `body.dark`, producing white cards on a dark page; both the semantic `--diff-*`/`--tl-*`/`--tok-*` aliases and the legacy ones are now redeclared in `body.dark`.) **No webfont is loaded**: `reset.css` used to `@import` IBM Plex Mono from `fonts.googleapis.com`, which stalled first paint on an offline/air-gapped machine and leaked a third-party request on every dashboard load — the one external dependency left after Chart.js was vendored. `--font-mono` still *prefers* `'IBM Plex Mono'` for anyone who has it installed locally, then falls back through the platform monospace faces (`ui-monospace`, SF Mono, Menlo, Consolas, DejaVu/Liberation Mono). Don't reintroduce a CDN font. The `body` is sans-serif and a small unscoped rule re-asserts `--font-mono` on code/diff/value surfaces (`pre, code, .diff-view, .code-diff, .source-view, .tl-code-preview, .code-changes, .var-changes, .reproduce-cmd, .cmd-code, .export-panel pre`). Timeline event types are distinguished primarily by **icon + plain-language label** (see below) with mostly-neutral left bars and the accent reserved — not five saturated hues

- **Legible Timeline event taxonomy**: `js/timeline.py` defines one `evMeta` map (icon, plain label, one-line meaning, color) used by the filter bar, the per-event type chip, hover `title=` tooltips, **and** a compact always-visible `.tl-legend` key rendered above the event list. Labels are plain language — `cell_exec`→"Code run", `var_set`→"Variable set", `artifact`→"Output saved", `metric`→"Metric", `observational`→"Ran, no change" (was the jargon "observe"), `resume`→"Resumed" — and icons are a coherent set (▶ / = / ↓ / # / · / ↻) replacing the old ad-hoc `>>`/`..` glyphs. The filter-bar labels match (also fixing a prior off-by-one where the `resume`/`lineage` buttons showed the wrong text). The row **badges** are de-jargoned and de-crowded: a code-run row shows **at most one** status chip (`new`, else `edited`, else `rerun`), explained by a second `.tl-legend-badges` "Badges:" key. The internal parent-hash "lineage" term never surfaces and there's no separate `← earlier version` chip — when an `edited` cell has a parent it gets `.tl-badge-link` (dotted underline) and *is itself* the click-to-view-earlier-version affordance (hash only in the tooltip); the filter button is **Edited cells**. There's no `result` chip either — the cell's output shows once in a neutral-mono `.tl-cell-output` **Out** panel (captured `print()` stdout + the trailing-expression repr, see the **Notebook cell output capture** pattern), distinct from the **Output saved** artifact event (a file). The Out panel renders *last* in the row so it always sits below the code, and `viewCellSource` inserts the expanded full source *above* it (`.tl-cell-output` lookup) so the output never floats above the code. **The per-row left number is execution order** — rendered `#<seq>` (with a hover tooltip) so it doesn't read as a line or cell number; code-run rows additionally show a small grey `.tl-cellpos` `cell N` chip from `ev.cell_pos` (the notebook cell position, suppressed for scripts / cell 0). **A code-run row shows exactly one cell label** (`cellLabelChip`): the `cell N` position chip when `ev.cell_pos` is known, otherwise a fallback derived from the stored `ev.key` reformatted (`cell_1` → `cell 1`) for scripts / pre-`cell_pos` runs. The raw internal `cell_<exec_num>` key (`ev.key`) is never rendered alongside the chip — rendering both `cellNumChip` and `<strong>ev.key</strong>` previously produced a duplicate "cell 1" + "cell_1" on the same row

- **Shared code rendering (syntax highlighting + word-level diffs)**: `js/highlight.py` is the single source of truth for rendering Python in the dashboard, used by both the Sessions tab and the experiment detail view. `_highlightPy(line)` is a dependency-free tokenizer (keywords/strings/comments/numbers/decorators/builtins/function-calls; every token HTML-escaped as emitted so it's injection-safe). Token colors are theme-aware `.tok-*` classes defined **unscoped** in `css/code.py`, reading a small, calm `--tok-*` palette centralized in `css/reset.py` so both views (and both themes) stay coordinated. For diffs, `_renderUnifiedDiff(diffText)` (raw `git diff` string) and `_renderCodeChangeParts(value)` (the `; `-joined `_code_change/cellN` summary fragments — parsed through `_normalizeSourceDiff`, the **one** reader of that storage format, since the format is still moving and two parsers drift) both build `{kind:'add'|'del'|'ctx'|'hunk', text}` rows and pass them to `_diffRowsToHtml`, which **pairs a run of consecutive deletions with the immediately-following run of additions and word-diffs each pair** — `_wordDiffPair` tokenizes both lines, runs an O(n·m) token LCS (`_tokenLcs`, guarded to fall back to plain highlighting past 40k token-pairs), and wraps only the changed span in a `.dword-add` / `.dword-del` pill while syntax-highlighting the unchanged runs around it. So an in-place edit like `threshold=0.7` → `0.5` spotlights just the `7`/`5` instead of two near-identical red/green lines. The pill is styled for legibility — a soft tint (`--diff-add-bg`/`--diff-del-bg`) plus a colored underline (`box-shadow: inset 0 -2px 0 var(--diff-*-bar)`, with a strikethrough for deletions) carries the add/remove signal while keeping normal ink rather than whiting out the token, so the changed span stays readable when a long line is expanded (the changed span is plain escaped text — never `.tok-*` — so there's no longer any in-pill token rule). **The word-pill spotlight is gated by similarity** — `_wordDiffPair` computes a Dice ratio (`2·common / (aReal+bReal)` over non-whitespace tokens) and, below 0.5, treats the pair as a rewrite rather than a tweak and falls back to plain per-line highlighting, so big changes don't turn into word-pill confetti. **The whole word-diff layer is user-toggleable** — `_diffRowsToHtml` consults `_wordDiffEnabled()` (localStorage `exptrack-word-diff`, default on) and, when off, never pairs del/add runs so every diff renders as plain line-level add/remove; the toggle lives in Settings → Display (**Highlight word-level diff changes**, wired via `setWordDiff()` in `js/core.py`, which re-renders the open detail view on change). **Green/red are reserved for added/removed**: `--tok-str` (strings) shares the amber `--tok-num` value rather than the success-green, so a string literal never reads as an added line even outside a diff. Diff lines render as `.code-diff > .dl` rows with a background tint + left bar (`--diff-add-bg`/`--diff-del-bar` etc., the same vars the Sessions split-diff uses) and a sign gutter. **Inside a diff, color carries only one meaning — added vs. removed:** `css/code.py` mutes the syntax `.tok-*` colors to plain ink within `.code-diff` (comments → `--text-3`) so a green string literal can't be misread as an "added" line. The red/green tints + sign gutter + word-pills carry all the change semantics; non-diff code surfaces (`.tl-code-preview`, `view source`) keep full syntax highlighting since they have no add/del meaning to collide with. Consumers: `js/detail.py` (Code Changes + Uncommitted-Changes git diff), `js/timeline.py` (`source_diff` previews + `viewCellSource` full source). **`viewCellSource` renders the *full* cell source as a diff when the cell has a parent** — `_lineDiffRows(parent, current)` (a line-level LCS in `js/highlight.py`, capped at 4M line-pairs) turns unchanged lines into `ctx` and changed lines into del/add runs, then `_renderDiffRows` word-diffs them, so expanding an edited cell spotlights the changed token across the whole source (not just the short timeline preview) and honors the word-diff toggle. No parent (or a source too large to diff) falls back to plain highlighted source with the previous version dimmed via `opacity`. **`_lineDiffRows` collapses long runs of unchanged context itself** (`_collapseDiffContext`, `DIFF_CONTEXT_LINES` = 3, matching git's default; pass `fullContext` to opt out) rather than leaving it to each call site: rendering every line of a 500-line file to spotlight two is a property of *this* output, so a third consumer can't forget the call and regress. Fold rows are `{kind:'fold', count}` and `_diffRowsToHtml` advances both line counters by `count`, or every number below a fold is wrong. **Code diffs carry an old/new line-number gutter** — `_diffRowsToHtml(rows, lineNumbers)` / `_renderDiffRows(rows, lineNumbers)` emit a `.dl-no` gutter (`.code-diff-numbered`) tracking old- and new-file line counters; `_renderUnifiedDiff` (git diff) seeds them from the `@@ -a,b +c,d @@` headers and the `viewCellSource` source diff starts at 1. Short fragment renders (the timeline `source_diff` preview, `_renderCodeChangeParts`) call `_renderDiffRows(rows)` with no line numbers since fragments have no real positions. Nested-box doubling is avoided with `.code-changes .code-diff` / `.diff-view:has(.code-diff)` overrides that strip the inner frame.

- **A class in the markup that no rule matches renders as a platform default, not as nothing**: `.btn-sm` and `.btn-ghost` were used by the parameter matrix's header, its floating selection bar and the toolbar's **Analyze** button, and were styled *nowhere* — there was no rule for either name in any stylesheet. A `<button>` with no styling does not fall back to the page's button look; it falls back to the **operating system's**, so those controls rendered in the system font at the system size with a grey bevel, ignoring the theme entirely (including dark mode). On a page where every other button shares one shape, that reads as an unfinished view rather than as three unstyled elements, and it is invisible to every check in the project: nothing raises, the bundle is valid, and the class name looks intentional in the markup. They are now defined in `css/components.css` as `.dc-button` one step smaller, since they sit in toolbars rather than dialog footers. The same class of failure produced the matrix's title: `_matrixShell` emitted an `<h2>`, and `css/table.css` styles a bare `h2` as an in-view **section heading** — 14px, uppercase, letter-spaced, muted — so the view announced itself in a treatment no other full-canvas view title used, purely by inheritance. The matrix now uses the shared header shell (`.compare-header`: a `.back-link` above a sentence-case `h3`). `tests/test_dashboard_js_integrity.py` asserts both — that the two button classes have rules in the assembled CSS, and that `_matrixShell` builds the shared header — because neither failure is visible from the code alone.

- **A borrowed rule brings its old constraints with it**: the scan-path editor (Images and Data Files) sets `width: 100%` inline and reuses `.name-edit-input` from the experiments table. That shared rule carries `max-width: 300px`, which is right where it was written — the table's editor sits in a fixed-width column and a wider input would paint over its neighbour — and wrong here, where the row is as wide as the panel. `max-width` beats an inline `width`, so the editor's own attempt to fill its row lost silently: a 300px box floating in a 1009px bar, on the one value most likely to be longer than the box you edit it in. Lifted for `.img-path-row` only, so the table keeps the cap it needs. The general shape: when markup borrows a class from another surface, the constraint that made that class safe *there* is inherited too, and `max-width`/`min-width` are the ones that win against the inline width a caller sets to opt out
