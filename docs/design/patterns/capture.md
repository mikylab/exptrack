# Capture

How params, metrics, artifacts, datasets and notebook cells get recorded without the user changing their code.

Detail for patterns indexed in `CLAUDE.md`. Each entry states the rule and the failure it prevents — the history is the point, so it is kept verbatim rather than summarized.

- **Zero-friction capture**: Argparse monkey-patching and IPython hooks intercept params without user code changes. **Every auto-capture patch must guard its own capture call**, because the patch runs *inside* the user's own call (`parse_args()`, `savefig()`, `add_scalar()`) — an unguarded failure propagates out of that call and aborts the run. The argparse patch (`_capture_namespace`/`_capture_remaining`/`capture_argv`) once didn't: `log_params` calls `json.dumps` on raw namespace values, so an argument with a non-serializable `type=` (a `Path`, an enum, a custom object) — or a `database is locked` during a parallel sweep — raised straight out of `parse_args()` and killed a run that would otherwise have trained. The matplotlib and TensorBoard patches wrapped their mirror calls from the start; argparse now matches them. The rule is invariant: if a patch calls back into exptrack from within a user library call, that callback is wrapped and degrades to a `debug_log`.

- **Diff-only storage**: Script changes are diffed against `git HEAD`; notebook snapshots store only cell diffs and variable change hashes — no full-source copies, keeps `.exptrack/` light

- **Content-addressed cell lineage**: Cells identified by SHA-256 of source content, parent found via 30% SequenceMatcher similarity. Handles cell reordering and splits. **Magic-only cells are excluded from lineage** (`is_magic_only`) — `%exptrack checkpoint/branch`, `%load_ext`, etc. are commands, not editable code, so they get no parent, no diff, and no `new`/`edited` badge in the Timeline, and are not offered as parents for real code cells. The Timeline view also guards at render time (`_isMagicOnlyCell`) so runs captured before this fix still display cleanly

- **Project root detection**: Walks parent directories looking for `.git` or `.exptrack/`

- **stdout/stderr separation**: Shell pipeline commands (`run-start`) output `export` statements to stdout so `eval $()` works; all status messages go to stderr

- **Auto artifact linking**: `plt.savefig()` is monkey-patched so saved plots auto-register as artifacts. Figures saved before experiment creation are buffered and flushed. **`savefig` also accepts a file-like target** (`io.BytesIO`, an open file) — a standard idiom for embedding or serving a plot — and there is no filesystem path to capture for those. The patch must detect a non-`(str, bytes, os.PathLike)` `fname` and return before path handling: `_P(str(fname)).resolve()` on a buffer fabricates a bogus path from the object's `repr`, which produced a `No such file` warning on stderr and a phantom `artifacts` row (NULL hash/size) on *every* in-memory save. The save itself always runs first, so skipping capture never affects the user's output

- **TensorBoard metric auto-capture**: `capture/tensorboard_patch.py` monkey-patches `SummaryWriter.add_scalar`/`add_scalars`/`add_histogram` (on both `torch.utils.tensorboard` and `tensorboardX`) so any scalar/loss/activation-histogram already routed through TensorBoard is *mirrored* onto the active experiment's `metrics` table — the metrics analogue of the savefig→artifact patch. This is the **only** auto-capture path for metrics (params are auto-captured via argparse; metrics otherwise require an explicit `exp.log_metric()`/notebook/CLI/pipeline call). `add_scalars` expands to `<main_tag>/<sub_tag>` keys; `add_histogram` summarizes the tensor/array to `<tag>/{mean,std,min,max}` (numpy, skipped if absent). No new dependency — it patches the writer at the call site rather than parsing `.tfevents` (which would need `tensorboard`/`protobuf`), so it only captures values logged *after* the patch installs (nothing retroactive from old `.tfevents` files), and a loop that only `print()`s a loss still needs an explicit `log_metric` (no library call to intercept). Because the writer module is usually imported by the user's script *after* patching (patching runs before the script), it patches already-imported writers and registers a one-shot `sys.meta_path` import hook so later imports are patched too. Retargeting mirrors argparse's `_active_exp` (script runs call `patch_tensorboard(exp)`), with a `_nb_state["exp"]` fallback so notebook runs retarget automatically. Installed in `__main__.py` (gated by `auto_capture.tensorboard`, default true) and both notebook start paths; originals always run and every mirror is best-effort (never crashes the user's run). **It also patches `SummaryWriter.__init__` to record the writer's log directory** (`_writer_log_dir` asks `log_dir` → `logdir` → `get_logdir()`, since torch and tensorboardX have differed) as a `[dir] tensorboard` artifact — reusing the label convention `exptrack link-dir --label tensorboard` already wrote, so the dashboard, the delete preview and the cleanup path treat auto-captured and hand-linked dirs alike. Mirroring the *values* without recording *where they were written* was only half the integration: `SummaryWriter()` with no `log_dir` creates `runs/<timestamp>_<hostname>/` itself, which is outside `outputs/` and therefore invisible to the storage report and to `find_orphan_output_paths`, so a project accumulated one orphaned event-file tree per run with nothing accounting for them

- **Auto output detection**: After a script finishes, `_auto_detect_outputs` scans the working directory for new files (images, models, data) created during the run and registers them as artifacts. Deduplicates against already-registered artifacts. Recognizes `.pt`, `.pth`, `.ckpt`, `.safetensors`, `.h5`, `.onnx`, `.pkl`, and other common ML file types

- **Dataset/input versioning**: When a run finishes (`Experiment.finish()`, so scripts, notebooks, and programmatic runs all covered — runs before the `_finished` guard so `log_params` still works), `core/dataset.py:capture_dataset_manifest(exp)` scans the run's captured params for dataset-shaped values (existing data files by extension — `.csv`/`.parquet`/`.npy`/`.h5`/… — or a dataset-shaped key like `--data_dir`/`--train`/`--test` pointing at any existing path) and records a `_dataset_manifest` param: per input a `{kind, path, size, hash}` (files partial-hashed; directories fingerprinted by their sorted `(relpath, size)` listing with no byte reads, so multi-GB datasets stay fast — capped at 5000 entries with a `truncated` flag). `_`-prefixed so it's skipped by run-naming and the param overwrite-warning. `get_experiment_detail` pops it out of `params` into a dedicated `datasets` key (so it never renders as a giant param row); the dashboard shows a **Datasets** section in the detail overview (path · size · 12-char fingerprint, `~` marks a partial hash). Best-effort — a failure here never crashes the user's run

- **Failure capture (traceback, not just a message)**: When a wrapped script crashes, `Experiment.fail(error, traceback=…)` stores the short message as the `error` param (backward compat) **and** the full formatted traceback (file + line) as the `_error_traceback` param — `_`-prefixed so it's skipped by run-naming and the param overwrite-warning, capped at `_MAX_TRACEBACK_CHARS` (20k). `get_experiment_detail` pops it out of `params` into a dedicated `error` key, and the dashboard detail view renders a **Run failed** panel (`.error-panel`, with a Copy button) on failed runs. The `__main__.py` crash handler prints the traceback *before* `_restore_streams` so it also lands in `stderr.log` (the restore closes the log files). The `SystemExit` path matters as much as the bare-`raise` path: a script that catches an exception and calls `sys.exit(1)` (common with frameworks/CLIs) would otherwise record only `SystemExit(code)` — the handler now follows `SystemExit.__context__` to the real chained cause and surfaces *that* traceback (terminal + log + DB), while a deliberate `sys.exit(code)` with no chained cause just records the code. The `Experiment.__exit__` context-manager path captures the traceback too (via the `exc_tb` it's already handed), so any `with Experiment(...)` block records the failing file + line, not just the message. Best-effort — capturing the traceback never crashes the failure path

- **No-copy artifact tracking, through one writer**: Artifacts are tracked by reference (path + hash in DB) — exptrack never copies or moves user files. Resume workflows and large checkpoint directories are unaffected. **`core/db.register_artifact` is the one implementation** of "record an artifact": resolve the path, hash the content, then check-before-insert on `(exp_id, resolved_path)`. Seven writers reached that row and only two went through it — `run-finish`'s output scan, `log-output`, `log-dir` (twice) and the dashboard's Add Artifact each wrote a bare INSERT with the path as given and no hash, so those artifacts were invisible to `exptrack verify`, unmatched by the rename and delete paths (which compare resolved paths), and duplicable. A reader that looks a row up by path — `api_delete_artifact` — has to normalize the same way the writer did, or it matches nothing and reports success

- **Auto-resume detection**: When `exptrack run` sees `--resume` (or any flag in `resume_flags` config) in the script's argv, it automatically resumes the latest experiment for that script instead of creating a new one. All metrics, artifacts, and params aggregate into the same experiment. Timeline seq and stdout/stderr logs append. Shell pipelines use `exptrack run-start --resume [EXP_ID]` explicitly. Programmatic: `Experiment.resume(exp_id)`

- **Plugin system**: Plugins loaded dynamically from `exptrack.plugins.<name>`, each module exports `plugin_class`. 4 lifecycle hooks

- **Per-project storage**: DB + notebook history in `.exptrack/` (gitignored), config.json is committable

- **Notebook cell output capture (print + returned value)**: A `pre_run_cell` hook installs a `_StdoutTee` on `sys.stdout` that writes to both the real stream (so output still shows in the notebook) and a `StringIO` buffer; `_collect_stdout_capture()` runs at the very top of `_post_run_cell` (before any early return) to read the buffer and restore the original stream, so the tee can never leak — and it only restores if the tee is still the active stream, leaving alone any `sys.stdout` the user's own cell swapped in. `_combine_cell_output(stdout_text, result_repr)` merges the captured stdout with the trailing-expression repr (prints first, then the returned value, mirroring the notebook), capped at `_MAX_CELL_OUTPUT` (4000 chars). The combined blob flows to the same two consumers as before: the experiment timeline event's `output_preview` (stored whole, no longer truncated to 200 chars) and the active session node via `record_cell(source, output)`. The dashboard renders it in a `.tl-cell-output` **Out** panel (multi-line `<pre>`, scrollable past ~220px, neutral `--border-strong` left bar — green is reserved for "added"; the Sessions `.cell-output`/`.node-latest-result`/`.cmp-result` blocks were switched to the same neutral bar) styled to match the Sessions tab. The panel is the **last** element in a Timeline row so it sits below the code, and `viewCellSource` inserts the expanded full source *before* the `.tl-cell-output` element so the result never floats above the code. **Timeline seq ordering**: the `pre_run_cell` hook also reserves the cell_exec event's seq up front via `Experiment.reserve_timeline_seq()` (stored in `_nb_state["_reserved_seq"]`, passed to `log_event(..., seq=…)` in `_emit_timeline_events`), so an artifact saved *mid-cell* (`plt.savefig` → `log_event`) gets a later seq and the "Output saved" event sorts **below** the "Code run" event instead of above it

- **Metric source tracking**: Metrics tagged as auto/manual/pipeline via `source` column. Manual metrics cannot overwrite auto points at the same step. Metrics table splits rows by source for clarity

- **Param source tracking**: Params tagged as auto/manual via `source` column. Auto params (captured by argparse/argv) are read-only in the dashboard; manual params (added via the manual-experiment modal or the per-experiment "+ Add Param" form) can be edited, renamed, or deleted inline. `+ Add Param` refuses to overwrite an existing key — to change a value, double-click to edit; to swap an auto key, delete is blocked, so pick a different key. Endpoints: `/api/experiment/<id>/{add-param,edit-param,delete-param,rename-param}`

- **A patch guards its own capture, and only its own capture**: the savefig hook wrapped the save *and* the whole registration path in one `try/finally` with no `except`, so a failure resolving the path, reaching the session subsystem or writing the artifact row would have propagated into the user's `plt.savefig()`. The save itself is the only thing allowed to raise; everything after it sits behind its own boundary (`_capture_saved_figure`)

- **Two capture paths must not record one knob twice**: under `exptrack run` both raw-argv and argparse capture fire, and when a flag's `dest` differs from its spelling (`--learning-rate` with `dest="lr"`) one hyperparameter landed under two keys — so "what varies" reported two axes for one knob. The argparse dest wins (it is what the script itself calls the value) and the shadowed argv key is retracted via `Experiment.forget_params`. The argv path also refreshes the run name, which it never did: a non-argparse script (click, manual `sys.argv`) never reaches `_capture_namespace`, so its name never picked up the captured params and two runs of different models were indistinguishable by name

- **A generated name may be regenerated; a chosen one may not**: both the argparse hook and the notebook HP capture called `_rename` unconditionally, so `%exp_start my-named-baseline` followed by a cell assigning `lr = 0.01` replaced the name the user had just chosen — while still reporting the run as user-named. Both paths now check `name_is_auto` first

- **A repo with no commits is not a capture failure**: `git diff` fails on an unborn HEAD because there is nothing to diff *against*, which is the normal state of a project in the minutes after `git init` + `exptrack init`. Recording `CAPTURE_FAILED` there made every early run claim its capture had broken. `NO_COMMITS` is a fourth diff sentinel, registered with the other three (`is_diff_sentinel` / `diff_sentinel_kind`) so every reader classifies it rather than rendering the marker as diff text

- **A capture buffered on one path must be buffered on the others**: the savefig patch has always held figures saved before an experiment exists and flushed them at creation, while the TensorBoard patch dropped pre-experiment scalars on the floor — so the same "log first, start tracking a moment later" shape (a notebook, a writer built at import time) lost metrics but kept plots. `_pending_metrics` closes the asymmetry, bounded at 2000 points because this can also legitimately *never* flush: a script that uses TensorBoard and never creates a run must not accumulate its whole training history in memory. Any truncation is stated on flush
